# 呼吸森林 AI 小助手 V1 用户场景与流程

## 1. 通用入口流程

```text
用户输入
  → 输入有效性与安全检查
  → 加载当前会话最小状态
  → 优先处理待确认或待澄清
  → 本地快速路由；必要时调用模型提取语义证据
  → 固定路由到聊天、知识、状态查询、单设备控制、固定场景、模拟优化或任务管理
  → 固定代码生成计划并执行策略裁决
  → 允许 / 确认 / 澄清 / 拒绝
  → 仅依据可信状态或执行回执生成回复
```

任何模型理解结果都不能直接成为设备执行结果。

## 2. 场景 S1：简单聊天与空气知识问答

### 用户目标

用户与 Luna 简短交流，或询问空气质量、通风和设备使用的一般性知识。

### 主流程

1. 用户发送问候或知识问题；
2. 系统识别为非执行类请求；
3. 模型生成简洁回答；
4. 涉及健康问题时附带适当边界，不声称诊断或环境绝对安全。

### 边界与异常

- 问题要求实时环境事实时，必须转入可信环境状态查询；
- 模型不可用时，返回简短降级说明；
- 用户描述明显急性不适或危险暴露时，建议先离开风险环境并寻求专业帮助；
- 回答不得触发设备动作。

## 3. 场景 S2：查询当前环境

### 用户目标

用户询问“现在空气怎么样”或指定当前环境指标。

### 主流程

1. 系统读取可信的当前环境快照；
2. 返回用户询问的指标、观测时间和数据来源；
3. 若用户没有指定指标，返回简要综合状态，并突出异常指标。

### 边界与异常

- Mock 数据必须明确标记为 Mock；
- 数据缺失、无效或超过后端约定的新鲜度阈值时，不描述为当前状态；
- 查询失败时不使用历史聊天或模型猜测补值；
- 用户追问医学影响时转入一般性知识回答，不做诊断。

## 4. 场景 S3：查询当前设备

### 用户目标

用户询问某个设备是否接入、在线或处于什么状态。

### 主流程

1. 系统从设备注册表解析唯一设备；
2. 读取连接状态和当前状态；
3. 返回设备名称、是否可操作、当前状态和数据来源。

### 边界与异常

- 多个候选设备时要求用户选择；
- 新风系统、加湿器和循环风机可显示“待接入”，但不可控制；
- 状态未知或读取失败时明确说明未知，不沿用旧消息中的状态；
- “它怎么样”只有在当前会话存在最近唯一设备时才能解析。

## 5. 场景 S4：单设备即时控制

### 用户目标

用户明确开关空气净化器、抽油烟机或智能窗户。

### 主流程：净化器或抽油烟机

1. 用户说出唯一设备和目标状态；
2. 系统校验设备接入、能力、当前状态和策略；
3. 若目标状态已满足，返回幂等结果，不重复执行；
4. 若策略允许，生成确定性计划并执行；
5. 收到可信回执后，返回成功或失败以及实际状态。

### 主流程：智能窗户

1. 用户提出打开或关闭智能窗户；
2. 系统展示设备、目标状态和影响摘要；
3. 系统保存有有效期的待确认计划；
4. 用户确认后，系统重新校验计划和设备状态；
5. 校验通过才执行，并按回执回复。

### 边界与异常

- 缺设备、缺动作或指代不唯一：澄清；
- 设备离线、未接入、状态未知或动作不支持：不执行；
- 确认已取消、过期或绑定状态已变化：旧确认失效，要求重新发起；
- 用户说“取消”时只取消当前待确认计划，不执行原动作；
- 执行超时或失败：说明失败，不声称设备已改变；
- 一次请求包含多个设备控制：说明 V1 只支持单设备控制并要求拆分。

## 6. 场景 S5：创建烹饪/火锅空气守护

### 用户目标

用户希望在做饭或吃火锅时启动固定空气守护。

### 主流程：立即开始

1. 用户请求“现在开始火锅空气守护”；
2. 系统匹配固定场景模板；
3. 系统检查抽油烟机、空气净化器以及可选智能窗户的状态和约束；
4. 系统展示固定动作、启动时间、“运行至用户停止”和模拟/设备来源；
5. 用户确认；
6. 系统重新校验后创建唯一活动任务并执行到期动作；
7. 系统按真实回执逐项说明结果，不把部分成功描述为全部成功。

### 主流程：当天定时开始

1. 用户给出当天未来的明确时间；
2. 系统解析为带时区的具体时间并回显；
3. 用户确认后创建待运行任务；
4. 到达时间时重新校验设备和策略后执行。

### 边界与异常

- 时间已过去、含糊或跨日：不创建，要求改为立即或提供当天未来时间；
- 用户未明确是否允许改变窗户状态：场景不得自行改变窗户；
- 场景模板的必要设备不可用：说明缺失设备，不创建任务；
- 已有活动任务：询问保留还是替换；只有确认替换后才停止旧任务并创建新任务；
- 模型只能识别场景证据，不能增减模板动作；
- 创建成功不等于设备动作成功，回复必须区分任务状态与每项执行回执。

## 7. 场景 S6：创建模拟优化任务

### 用户目标

用户选择舒适优先、均衡自动或低碳优先，让系统启动持续模拟优化。

### 主流程

1. 用户说出一个明确模式；
2. 系统展示模式、固定目标、可控设备范围、“模拟优化”标识和持续至用户停止；
3. 用户确认；
4. 系统创建唯一活动任务；
5. Mock 或 Replay 仅产生候选动作；
6. 候选动作经过动作屏蔽、策略裁决和执行器；
7. 系统仅依据可信回执更新任务并回复。

### 边界与异常

- 未选模式：列出三个固定模式并要求选择；
- 请求自定义权重或真实在线 DQN：说明 V1 不支持；
- 已有活动任务：询问是否替换，不静默覆盖；
- Mock/Replay 不可用：不创建任务；
- 候选动作涉及离线、未接入或不允许的设备：屏蔽该动作；
- 没有可执行候选动作：任务可保持活动，但必须说明本轮未执行动作；
- 不得宣称真实节能、健康或舒适收益。

## 8. 场景 S7：管理当前唯一任务

### 查询

用户询问“当前是什么模式/任务”时，返回任务类型、模式或场景、状态、开始或计划时间以及“模拟优化”标识。

### 暂停

1. 仅活动中的任务可以暂停；
2. 暂停成功后不得继续产生或执行新动作；
3. 已暂停时再次暂停，返回幂等状态。

### 恢复

1. 仅暂停中的任务可以恢复；
2. 恢复前重新校验依赖、设备和策略；
3. 校验失败则保持暂停并说明原因；
4. 已运行时说“继续”，返回当前状态，不重复启动。

### 停止

1. 活动、暂停或待运行任务均可停止；
2. 停止后不再调度新动作；
3. 停止不等于自动反转已经完成的设备动作；
4. 无当前任务时返回“当前没有活动任务”。

### 边界与异常

- “暂停/继续/停止”只作用于当前唯一任务；
- 存在待确认计划时，“取消”优先取消该计划；
- 状态变更失败时保留原状态并允许重试；
- 任务查询不得依赖模型记忆猜测。

## 9. 场景 S8：当前会话确认、澄清与指代

### 确认

- “确认”只接受当前唯一、未过期且仍有效的待确认计划；
- “取消”“不用了”清除待确认计划；
- 没有待确认计划时，“确认”不得触发最近一次历史动作。

### 澄清

- 系统一次只询问完成当前意图所需的最少信息；
- 用户补充后必须合并原请求并重新校验；
- 用户改变话题时清除不再适用的待澄清状态。

### 简单指代

- 当前会话最近唯一设备可被“它”引用；
- 当前唯一任务可被“这个任务”引用；
- 跨日、跨会话或多个候选对象时必须重新选择。

## 10. 场景 S9：依赖故障与安全降级

| 故障 | 用户可继续使用 | 系统行为 |
|---|---|---|
| 聊天模型不可用 | 当前状态查询、明确本地控制、任务管理 | 固定模板回复；不可靠的自然语言请求不执行 |
| 环境数据不可用 | 聊天、设备查询与允许的设备控制 | 明确环境数据不可用，不猜测数值 |
| 设备服务不可用 | 聊天和一般知识 | 不执行设备动作，不声称成功 |
| Mock/Replay 不可用 | 聊天、查询、允许的单设备控制 | 不创建或继续产生模拟优化动作 |
| 回复模型不可用 | 其他链路按自身状态运行 | 使用基于回执的固定模板 |
| 执行超时 | 非执行类能力 | 标记失败或未知，允许查询和重试 |

## 11. 前端入口需求

- V1 首先通过 AI 对话支持烹饪守护与三种模拟优化模式；
- 当前“回家、深呼吸、静享、低碳”快捷场景不得自动映射成未经定义的 V1 任务；
- 前端后续应提供任务摘要、确认/取消、待澄清、活动任务状态、“模拟优化”标识和失败/部分成功状态；
- 在共享契约与实现完成前，现有 UI 继续明确标注 Mock。
