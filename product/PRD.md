# 呼吸森林 AI 小助手 V1 PRD

## 1. 文档状态

- 状态：目标规格，待共享契约确认与实现
- 版本：V1
- 日期：2026-08-03
- 产品决策：`decisions/D-2026-08-03-AI-ASSISTANT-V1-SCOPE.md`

本文定义下一阶段“呼吸森林 AI 小助手 V1”的产品目标，不表示当前 UI、后端、模型或设备链路已经实现。当前可运行基线仍是本地 UI Mock；任何 Mock、Replay 或本地结果都不得描述为真实设备、生产 AI、真实 DQN 或正式上线能力。

## 2. 产品目标

V1 让用户在一个会话内安全地完成五类任务：

1. 简单聊天和空气质量、设备知识问答；
2. 查询当前环境指标与当前设备状态；
3. 控制一个明确且已接入 V1 的设备；
4. 创建并管理一个固定的烹饪/火锅空气守护任务；
5. 创建并管理一个舒适优先、均衡自动或低碳优先的模拟优化任务。

V1 的核心承诺不是“模型可以控制一切”，而是：自然语言理解、确定性执行计划和可信执行结果相互分离；任何动作均经过设备能力校验、安全策略和执行回执后，才能向用户陈述结果。

## 3. 目标用户与核心需要

### 3.1 家庭空气管理者

希望快速了解当前空气状况、开关常用空气设备，并在做饭或吃火锅时启动固定守护任务。

### 3.2 希望减少操作负担的用户

希望选择明确的优化目标，让系统在模拟环境中持续权衡健康、舒适和低碳，同时保留暂停、恢复和停止权。

### 3.3 仅咨询空气知识的用户

希望获得易懂的一般性空气与设备知识，但不应把回答误认为医疗诊断或专业医疗建议。

## 4. V1 能力范围

### 4.1 支持

- 通用问候和简短聊天；
- 一般性空气质量与设备知识问答；
- 当前 `PM2.5`、`CO2`、湿度、温度、空气评分和观测时间查询；
- 当前设备连接状态和开关状态查询；
- 空气净化器、智能窗户、抽油烟机的单设备即时控制；
- 固定烹饪/火锅空气守护；
- 舒适优先、均衡自动、低碳优先三种固定模拟优化模式；
- 同时至多一个活动自动化任务；
- 当前任务的查询、暂停、恢复和停止；
- 当前会话最近几轮上下文；
- 待确认、待澄清和最近唯一设备的简单指代；
- Mock 或 Replay 优化结果；
- 基于本地可信状态生成的执行回执；
- 模型不可用时的安全降级。

### 4.2 V1 设备范围

| 设备 | V1 查询 | V1 控制 | 状态词 | 备注 |
|---|---:|---:|---|---|
| 空气净化器 | 是 | 是 | `on` / `off` | 明确、幂等开关可直接执行 |
| 智能窗户 | 是 | 是 | `open` / `closed` | 直接执行，仍需能力/状态版本/策略/回执校验 |
| 抽油烟机 | 是 | 是 | `on` / `off` | 明确、幂等开关可直接执行 |
| 新风系统 | 可展示接入状态 | 否 | 不定义 | V1 标记“待接入” |
| 加湿器 | 可展示接入状态 | 否 | 不定义 | V1 标记“待接入” |
| 循环风机 | 可展示接入状态 | 否 | 不定义 | V1 标记“待接入” |

设备自然语言名称只能作为候选证据；最终设备 ID、能力和当前状态必须来自可信设备注册表。

### 4.3 固定烹饪/火锅空气守护

- 入口：AI 对话；快捷场景 UI 调整作为前端后续需求；
- 启动方式：立即开始，或在当天指定时间开始；
- 固定动作骨架：抽油烟机开启、空气净化器开启；智能窗户仅在用户明确选择且策略允许时改变状态；
- 创建前必须展示任务摘要并要求用户确认；
- 启动后持续运行，直到用户停止；
- 不支持跨日排程、循环日程、复杂条件或模型自由增减设备动作。

### 4.4 三种模拟优化模式

| 模式 | 用户目标 | V1 产品表述 |
|---|---|---|
| 舒适优先 `comfort` | 在健康底线内优先体感舒适 | 模拟优化 |
| 均衡自动 `balanced` | 平衡健康、舒适与能耗 | 模拟优化 |
| 低碳优先 `eco` | 在健康底线内降低能耗 | 模拟优化 |

- 模式名称、目标权重、可控设备范围和健康硬底线由固定配置定义；
- V1 只允许 Mock 或 Replay，不支持 `live_model`；
- 创建模式任务前必须确认；
- 页面和回复必须明确展示“模拟优化”，不得声称已产生真实健康、舒适或节能收益；
- 同时只允许一个活动任务。新任务与现有任务冲突时，必须询问用户是否替换，不得静默覆盖。

## 5. 确认与执行规则

### 5.1 可直接执行

满足以下全部条件的空气净化器、抽油烟机或智能窗户单设备开关可直接执行：

- 用户明确说出唯一设备和目标状态；
- 设备在 V1 可控范围内且当前可用；
- 动作为该设备允许的动作；
- 不涉及定时、场景、优化任务或现有任务替换；
- 策略未要求确认、澄清或拒绝。

若目标状态与当前状态一致，返回“已经处于该状态”，不得制造重复执行成功记录。

### 5.2 必须确认

- 创建固定烹饪/火锅守护任务；
- 创建任一模拟优化任务；
- 用新任务替换当前活动任务。

确认必须绑定具体计划、状态版本和有效期。计划、设备状态或活动任务发生变化后，旧确认不得继续执行。

### 5.3 智能窗户免确认执行

智能窗户状态改变在 V1 中不再要求用户确认，直接进入执行链路，但必须保留以下安全校验：

- 设备能力校验：设备已接入、在线、状态已知且动作受支持；
- 状态版本校验：计划生成时的状态版本与执行时一致，版本变化则放弃执行；
- 策略裁决：通过策略允许后才执行；
- 可信执行回执：仅在收到成功回执后陈述成功，失败、超时或未知状态不得陈述成功；
- 来源标识：执行结果与设备状态保持 Mock/Replay/真实来源标识。

### 5.4 必须澄清

- 未说明设备或目标状态；
- 同一名称对应多个设备；
- 时间表达无法唯一解析，或指定时间已经过去；
- “它”“继续”等指代无法由当前会话唯一解析；
- 用户只说“优化一下”但未选择模式；
- 当前任务与新请求冲突，但用户尚未选择保留或替换。

### 5.5 必须拒绝

- 空输入、超过契约限制的输入或无法安全处理的格式；
- 请求控制 V1 未接入设备；
- 请求跨日排程、复杂条件自动化、多任务并行或多设备自由组合；
- 请求自定义优化权重、真实 DQN、真实 MQTT 或绕过安全策略；
- 请求执行与设备能力、权限或安全约束冲突的动作；
- 无法可靠理解自然语言控制且本地规则也无法确认意图。

拒绝回复应说明不能执行的原因，并在可能时给出 V1 范围内的替代操作。

## 6. 会话范围

V1 只保留当前会话的最小状态：当前话题、最近唯一设备、活动任务、待澄清问题和待确认计划。

- 支持：“打开净化器”之后说“把它关掉”；
- 不支持：“按三天前那个方案来”或跨会话恢复指代；
- 用户取消待确认计划、完成澄清、计划过期或会话结束后，应清除相应临时状态；
- V1 不自动保存长期偏好，不使用历史聊天作为当前设备事实。

## 7. 模型与可信结果边界

### 7.1 模型可以做

- 普通聊天和一般性知识解释；
- 在普通聊天和空气健康知识问答中生成 `message.content` 的自然语言回复；回复仍使用对应的 `chat` / `knowledge` 响应类型，且来源和业务字段由固定链路维护；
- 提取用户原话中的设备、动作、时间、场景和模式证据；
- 理解当前会话内的简单指代；
- 基于可信状态、策略结果和执行回执组织自然语言回复。

### 7.2 模型不可以做

- 判断设备是否真实存在或决定最终设备 ID；
- 决定或修改 `responseType`、`sources`、计划、策略、任务、确认或回执等业务字段；
- 自由生成可执行计划；
- 决定动作是否安全或是否允许；
- 绕过确认、安全策略或设备能力；
- 直接调用设备；
- 在没有成功回执时声称动作成功；
- 把历史对话、Mock、Replay 或预测结果描述为实时设备事实。

### 7.3 真实模型 API 聊天与知识问答

本小节定义 V1 在接入真实模型 API 后，普通聊天与空气健康知识问答的产品边界。共享契约 `v1.0.0` 无需升级：模型仅参与生成 `message.content`，不改变 `responseType`、`sources` 或业务字段。

#### 可回答话题

- 通用问候和简短聊天；
- 空气质量基础概念：`PM2.5`、`CO2`、湿度、温度的含义与常见影响因素；
- 通风、设备使用和维护的一般性知识；
- V1 设备（空气净化器、智能窗户、抽油烟机）的原理和使用边界；
- 舒适优先、均衡自动、低碳优先模拟优化的概念和边界；
- 一般性健康影响说明（不做诊断、不替代医疗建议）。

#### 不可回答或必须转入其他链路的话题

- 当前环境或设备实时状态：必须转入可信状态查询，不得由模型推断数值；
- 设备控制、场景、任务或优化请求：必须转入确定性执行链路，模型不得生成执行结果；
- 跨会话或历史记忆引用：V1 不支持恢复；
- 真实 DQN、真实 MQTT、真实收益声明：明确拒绝；
- 个人疾病诊断、治疗建议或环境绝对安全承诺：拒绝并说明边界。

#### 降级口径

模型 API 不可用时，系统使用固定模板兜底：明确说明当前无法提供模型回答，并给出可用的替代能力；不得假装已回答、不得用固定文本冒充模型原回答，也不得在模型未返回内容时生成设备或环境状态结论。

## 8. 健康与安全边界

- 空气知识回答仅提供一般性信息，不进行疾病诊断，不替代医疗建议；
- 用户描述明显急性不适或危险暴露时，优先建议离开风险环境，并寻求当地紧急服务或专业医疗帮助；
- 不得仅凭模型回答否定用户症状或保证环境安全；
- 环境数值必须同时展示观测时间和数据来源；过期、缺失或 Mock 数据不得描述为当前真实环境。

### 8.1 免责声明统一口径

通用免责文案统一为：`Luna 是 AI 工具噢，我的回答仅供参考。`

涉及健康影响或症状的话题，在通用免责之外必须追加医疗强化句：`以上仅为一般性信息，不构成医疗诊断，也不能替代专业医疗建议。`

#### 触发判定口径

| 触发类型 | 判定依据（话题/关键词示例） | 必须出现的文案 |
|---|---|---|
| 通用免责 | 所有模型生成的聊天或知识回复 | `Luna 是 AI 工具噢，我的回答仅供参考。` |
| 医疗强化 | 健康影响、症状或医疗话题：`健康`、`危害`、`影响身体`、`呼吸困难`、`胸痛`、`头晕`、`咳嗽`、`过敏`、`哮喘`、`中毒`、`一氧化碳`、`医疗`、`诊断`、`治疗`、`症状`、`危险暴露`、`浓烟` 等 | 通用免责 + `以上仅为一般性信息，不构成医疗诊断，也不能替代专业医疗建议。` |

- 医疗强化句是追加关系，不得替代通用免责；
- 判定命中任一类医疗关键词即触发医疗强化句；
- 用户描述明显急性不适或危险暴露时，安全引导优先于两条免责文案，免责文案不得削弱安全引导；
- 模型不可用时使用固定模板兜底，模板同样遵守上述免责口径，不得假装已回答。

## 9. 降级原则

- 模型 API 不可用：普通聊天和知识问答使用固定模板明确说明当前无法提供模型回答，不假装已回答、不伪造知识结论；状态查询和高确定性本地控制仍可工作；无法可靠识别的自然语言控制不得执行；
- 回复生成失败：使用固定模板陈述可信状态、策略结果或执行回执；
- 实时天气或室外数值（E3）：V1 不接入外部实时数据源时不编造数值，明确回答不可得或拒绝该话题，不得用模型猜测补值；
- 超长输入（E4）：超过 4000 个 Unicode 字符的输入返回稳定输入错误，且该检查优先于语义路由、历史方案检查与模型调用；
- 环境数据缺失或过期：明确说明暂时无法获得可信的当前读数；
- 设备离线或状态未知：不执行动作，不声称成功；
- Mock/Replay 不可用：不得启动模拟优化任务，但普通聊天、查询和确定性单设备控制按各自依赖独立降级；
- 执行超时或失败：保留失败状态，允许用户重试或查询，不把请求已受理写成执行成功。

## 10. 非目标

- 实时网页搜索和外部实时信息检索；
- 多日聊天记忆和长期偏好；
- 多个并行任务；
- 任意多意图组合和多设备自由计划；
- 跨日或循环排程；
- 复杂条件自动化；
- 自定义优化权重；
- DQN `live_model`；
- 真实 MQTT 和真实设备收益验证；
- 跨家庭、家庭成员和复杂权限；
- 医疗诊断或个体化治疗建议。

## 11. 上线前置条件

V1 只有在产品验收标准、共享契约、前后端实现、契约测试和安全降级均完成后，才能从“目标规格”变更为可交付状态。真实模型、真实设备或外部服务的接入仍需单独授权和验证。
