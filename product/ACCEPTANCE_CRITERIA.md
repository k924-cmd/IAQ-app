# 呼吸森林 AI 小助手 V1 验收标准

## 1. 验收前提

- 本文是 V1 目标验收标准，不表示当前 UI Mock 已通过；
- 前端、后端必须基于协调窗口已接受并版本化的共享契约；
- 测试数据必须明确区分 Mock、Replay 和真实来源；
- V1 不接入真实 MQTT 或 DQN `live_model`；
- 验收不得使用旧 AI V1、Phase A、DQN 路线或历史报告作为通过证据。

## 2. 通用安全链路

- AC-000：给定空输入、超过契约长度上限的输入或无效格式，当系统接收请求时，应返回稳定的输入错误且不调用模型或执行器。
- AC-001：给定任一设备类自然语言请求，当模型返回语义候选时，系统不得把模型输出直接发送给执行器；必须经过设备解析、确定性计划和策略裁决。
- AC-002：给定没有成功执行回执的请求，当系统生成回复时，不得出现“已开启”“已关闭”“已执行成功”等成功陈述。
- AC-003：给定 Mock 或 Replay 数据，当 UI 或助手展示结果时，必须出现用户可见的来源标识，不得描述为真实设备或真实优化收益。
- AC-004：给定请求 ID 或幂等键重复提交同一计划，当系统处理请求时，不得重复执行设备动作。
- AC-005：给定内部错误，当错误展示给用户或写入运营事件时，不得包含内部堆栈、凭据、完整敏感对话或未脱敏个人信息。
- AC-006：给定提示注入或要求绕过规则的文本，当系统处理时，不得因此跳过设备能力、确认、策略或回执校验。

## 3. 聊天与知识

- AC-010：给定普通问候，当模型服务可用时，系统返回非执行类回复、不创建执行计划，且回复必须附统一免责文案 `Luna 是 AI 工具噢，我的回答仅供参考。`。
- AC-011：给定一般空气知识问题，当系统回答时，内容不得声称医疗诊断、不得替代专业医疗建议、不得否定用户症状或保证环境绝对安全；涉及健康影响或症状时，必须追加医疗强化句 `以上仅为一般性信息，不构成医疗诊断，也不能替代专业医疗建议。`，且医疗强化句不得替代通用免责文案。
- AC-012：给定用户描述明显急性不适或危险暴露，当系统回答时，应优先输出安全引导（建议离开风险环境并联系当地紧急服务或专业医疗人员），安全引导不得被一般性知识内容替代，且必须同时保留通用免责与医疗强化句。
- AC-013：给定聊天模型或回复生成模型不可用，当用户发送普通聊天或知识问题时，系统必须明确说明当前无法提供模型回答，并可返回固定模板兜底；不得假装已回答、不得伪造知识结论，且不得影响可独立工作的状态查询和本地高确定性控制。
- AC-014：给定可回答的聊天或空气健康知识问题，当真实模型 API 可用时，系统生成自然语言回答，且仅体现于 `message.content`，不改变 `responseType`、`sources` 或计划、任务、确认、回执等业务字段。
- AC-015：给定聊天或知识请求，当模型生成回复时，回复不得触发设备动作、创建执行计划或改变任务状态。
- AC-016：给定空气知识问题，当模型回答时，内容限于 V1 可答话题（空气质量概念、通风、V1 设备使用边界、模拟优化概念与一般健康影响说明）。
- AC-017：给定 V1 可答话题之外的问题（个人疾病诊断、治疗建议、实时天气预报、跨会话记忆引用等），当系统回答时，应拒绝或转入相应链路，不得以普通知识回答代替。
- AC-018：给定当前空气或设备状态类问题，当模型可用时，系统不得由模型推断数值，必须转入可信状态查询；模型回答不得包含编造的当前读数。
- AC-019：给定空气健康知识回答，当内容涉及健康影响或症状时，必须同时包含通用免责文案与医疗强化句 `以上仅为一般性信息，不构成医疗诊断，也不能替代专业医疗建议。`；通用免责与医疗强化句均不得省略。

## 4. 当前环境与设备查询

- AC-020：给定有效环境快照，当用户询问当前空气时，回复包含所需指标、`observedAt` 和数据来源。
- AC-021：给定环境数据缺失、无效或超过约定新鲜度，当用户查询时，系统明确说明无法获得可信当前数据，不使用模型或历史聊天补值。
- AC-022：给定 Mock 环境快照，当用户查询时，回复明确标识为 Mock。
- AC-023：给定唯一设备名称，当用户查询状态时，回复来自设备注册表和当前状态服务，并包含是否可操作。
- AC-024：给定多个同名候选设备，当用户查询或控制时，系统要求选择，不得自行决定设备 ID。
- AC-025：给定新风系统、加湿器或循环风机，当用户尝试控制时，系统说明 V1 未接入且不创建执行计划。
- AC-026：给定设备状态未知或读取失败，当用户查询时，系统返回未知或失败，不沿用旧消息中的状态。

## 5. 单设备控制

- AC-030：给定在线可控的空气净化器和明确目标状态，当策略允许时，系统可无需额外确认执行，并仅在成功回执后声明成功。
- AC-031：给定在线可控的抽油烟机和明确目标状态，当策略允许时，系统可无需额外确认执行，并仅在成功回执后声明成功。
- AC-032：给定在线可控的智能窗户和明确目标状态，当策略允许时，系统可无需额外确认直接执行，但必须完成设备能力校验、状态版本校验、策略裁决、可信执行回执与来源标识。
- AC-033：给定智能窗户直接执行请求，当目标状态已满足时，系统返回幂等结果且不产生新的设备执行记录；当执行失败、超时或状态未知时，系统不得陈述成功。
- AC-034：给定智能窗户直接执行请求，当计划生成后的设备状态版本在执行前发生变化时，系统放弃执行且不陈述成功，并要求用户重新发起。
- AC-035：给定设备已经处于目标状态，当用户重复请求时，系统返回幂等结果且不产生新的设备执行记录。
- AC-036：给定缺少设备、目标状态或指代不唯一，当用户请求控制时，系统只澄清缺失信息，不执行。
- AC-037：给定设备离线、未接入、能力不支持或策略拒绝，当用户请求控制时，系统不执行并说明原因。
- AC-038：给定执行失败或超时，当系统回复时，必须说明失败或状态未知，不得把“请求已受理”描述为执行成功。
- AC-039：给定一次请求包含多个设备动作，当系统识别后，应说明 V1 只支持单设备即时控制并要求用户拆分。

## 6. 烹饪/火锅空气守护

- AC-040：给定明确的立即启动请求，当系统生成任务摘要时，摘要包含固定必要动作、可选窗户行为、立即开始、持续至用户停止和数据/执行来源。
- AC-041：给定烹饪守护摘要，当用户未确认时，系统不得创建或启动任务。
- AC-042：给定用户确认且依赖仍有效，当系统创建任务时，任务使用固定场景模板，模型不得自由增减动作。
- AC-043：给定当天未来的明确时间，当系统创建待运行任务前，必须以带时区的具体时间回显并取得确认。
- AC-044：给定过去时间、含糊时间或跨日时间，当用户请求排程时，系统不得创建任务，并要求改为立即或当天未来明确时间。
- AC-045：给定用户没有明确选择改变窗户状态，当场景运行时，不得改变智能窗户。
- AC-046：给定必要设备不可用，当用户尝试创建场景时，系统不创建任务并说明缺失依赖。
- AC-047：给定场景动作部分成功，当系统回复时，必须逐项展示结果，不得把部分成功描述为全部成功。

## 7. 三种模拟优化模式

- AC-050：给定用户选择 `comfort`、`balanced` 或 `eco`，当系统展示确认摘要时，必须包含固定目标、设备范围、“模拟优化”标识和持续至用户停止。
- AC-051：给定用户只说“优化一下”，当没有明确模式时，系统列出三种模式并要求选择，不自行决定。
- AC-052：给定用户未确认模式任务，当系统处理请求时，不得创建活动任务。
- AC-053：给定有效确认，当任务创建时，只能使用 Mock 或 Replay，且输出只能作为候选动作。
- AC-054：给定 Mock/Replay 候选动作，当动作涉及离线、未接入、越权或不允许的设备时，动作屏蔽与策略必须阻止执行。
- AC-055：给定本轮没有合法候选动作，当任务仍活动时，系统明确说明本轮未执行动作，不伪造优化结果。
- AC-056：给定用户请求自定义权重、真实 DQN 或真实节能收益，当系统回答时，明确说明 V1 不支持。
- AC-057：所有模式页面、任务摘要、状态回复和结果回复均不得省略“模拟优化”标识。

## 8. 唯一任务与冲突

- AC-060：给定已有活动、暂停或待运行任务，当用户创建新任务时，系统询问保留还是替换，不静默覆盖。
- AC-061：给定用户选择保留旧任务，当系统处理冲突时，不创建新任务且旧任务状态不变。
- AC-062：给定用户确认替换，当系统处理时，必须先成功停止旧任务，再创建新任务；停止失败时不得创建新任务。
- AC-063：给定运行中的任务，当用户暂停时，任务进入暂停状态且不再产生或执行新动作。
- AC-064：给定暂停任务，当用户恢复时，系统重新校验依赖、设备与策略；校验失败时保持暂停。
- AC-065：给定活动、暂停或待运行任务，当用户停止时，任务停止调度新动作，但系统不得宣称已经自动反转历史设备动作。
- AC-066：给定没有当前任务，当用户查询、暂停、恢复或停止时，系统返回明确的无任务状态且不报伪成功。
- AC-067：给定重复暂停、恢复或停止请求，当目标状态已满足时，系统返回幂等状态且不重复执行状态迁移。

## 9. 会话确认、澄清和指代

- AC-070：给定当前存在唯一有效待确认计划，当用户说“确认”时，只能执行该计划。
- AC-071：给定没有待确认计划，当用户说“确认”时，不得执行历史动作。
- AC-072：给定当前存在待确认计划，当用户说“取消”或“不用了”时，计划被清除且不执行。
- AC-073：给定最近唯一设备，当用户在同一会话中说“把它关掉”时，可解析为该设备并重新经过完整安全链路。
- AC-074：给定没有最近唯一设备、存在多个候选设备或发生跨会话指代，当用户使用“它”时，系统要求重新选择。
- AC-075：给定待澄清问题，当用户补充缺失信息时，系统合并原请求并重新校验；不得绕过策略或确认。
- AC-076：给定用户明确改变话题，当原待澄清状态不再适用时，系统清除该状态。
- AC-077：给定跨日或跨会话的“上次那个方案”，系统不恢复历史计划并要求用户重新选择。

## 10. 故障降级

- AC-080：给定聊天模型不可用，当用户发出可由本地规则唯一识别的状态查询或允许的控制时，该能力仍可独立处理。
- AC-081：给定聊天模型不可用且本地规则无法可靠理解控制请求，系统不得执行并要求用户用受支持的明确表达重试。
- AC-082：给定回复生成模型失败，当已有可信结果时，系统使用固定模板准确展示该结果。
- AC-083：给定设备服务不可用，系统不得执行设备动作；聊天和一般知识能力可独立降级。
- AC-084：给定 Mock/Replay 不可用，系统不得创建新的模拟优化任务，也不得继续产生候选优化动作。
- AC-085：任一依赖故障不得导致单设备控制、任务创建、恢复或到期执行绕过设备能力校验、状态版本校验或策略复核；智能窗户免确认不降低上述校验要求。
- AC-095：给定实时天气或室外数值请求（如室外 `PM2.5`、室外温度、室外空气质量、天气预报），当 V1 没有可信的外部实时数据源时，系统明确回答不可得或拒绝该话题，不编造、不猜测数值，也不把室内快照描述为室外数据。
- AC-096：给定超过 4000 个 Unicode 字符的输入，当系统接收请求时，必须在语义路由、历史方案检查与模型调用之前返回稳定输入错误。

## 11. UI 与可访问性

- AC-090：V1 烹饪守护和三种模式可先从 AI 对话完成；现有快捷场景不得自动映射为未定义任务。
- AC-091：确认摘要提供清晰的确认与取消操作，且用户可以通过文本完成同等操作。
- AC-092：任务状态可区分待确认、待运行、运行、暂停、停止和失败，不只依赖颜色表达。
- AC-093：错误、拒绝、澄清、执行中、成功和部分成功在文案上可区分。
- AC-094：刷新或重连后，前端不得把仅存在于本地 UI 的旧 Mock 状态显示为后端可信状态。

## 12. 出口标准

V1 只有在以下条件全部满足时才能标记为可交付：

1. 本文所有适用验收项均有可重复的测试证据；
2. 共享会话、设备、环境、任务、确认、执行回执、错误和事件契约已达到 `accepted` 并完成版本化；
3. 前端与后端通过契约测试和 V1 关键路径集成测试；
4. Mock/Replay、真实能力和不可用状态在 UI 与回复中清晰区分；
5. 安全、隐私、日志脱敏和故障降级测试通过；
6. 产品线按原始验收条件复核，未通过降低断言或修改目标制造通过结果。
