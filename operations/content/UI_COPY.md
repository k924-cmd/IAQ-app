# V1 UI 与回复文案规范

## 1. 总原则

- Luna 语气温和、简洁、可操作，但不用模糊的积极语气掩盖失败、降级或未知。
- 模型理解、请求已受理、任务已创建和设备动作已成功是不同结果，不得混写。
- 只有 `succeeded` 可以使用“已打开/已关闭/已执行”；`noop` 只能写“已处于该状态”。
- 错误、拒绝、澄清、执行中、成功和部分成功必须有明确文字状态，不只靠颜色或图标区分。
- 不在用户文案中显示内部堆栈、依赖 URL、凭据、原始模型输入输出或内部错误消息。
- 健康内容只提供一般性信息，不诊断、不保证环境安全、不替代专业医疗建议。

## 2. Mock、Replay 与模拟优化

| 场景 | 必须展示 | 推荐文案 | 禁止表述 |
|---|---|---|---|
| 本地 Mock 环境或设备数据 | Mock 标识、观测时间 | `本地 Mock 数据 · 仅供联调`；`Mock 观测时间：{observedAt}` | `当前家中`、`实时传感器`、`真实设备状态` |
| Replay 数据 | Replay 标识、记录时间 | `Replay 回放 · 非实时数据`；`正在回放已记录的模拟输入` | `实时预测`、`正在感知`、`线上模型决策` |
| 优化任务摘要 | “模拟优化”、模式、固定目标、设备范围、持续至用户停止 | `将启动模拟优化：{modeLabel}。候选动作来自 {Mock/Replay}，仍会经过策略检查。` | `AI 已接管`、`DQN 正在控制`、`自动找到最优方案` |
| 模拟优化运行中 | 每次状态和结果都保留“模拟优化” | `模拟优化运行中。本轮候选动作已进入安全检查。` | `正在产生真实节能/健康/舒适收益` |
| 本轮无合法候选动作 | 任务仍在运行且本轮未执行 | `模拟优化仍在运行；本轮没有通过安全检查的动作，因此未执行设备操作。` | `已优化完成`、`已节能` |

模式用户可见名称固定为“舒适优先”、“均衡自动”、“低碳优先”。“低碳优先”是模拟目标，不等于已产生真实节能或减排收益。

## 3. 连接与依赖降级

| 状态 | 标题 | 推荐文案 | 用户可做什么 |
|---|---|---|---|
| 后端未连接 | `后端未连接` | `当前无法获取后端可信状态，页面只展示本地 Mock 内容。` | `检查本地服务后重试` |
| 刷新/重连中 | `正在恢复状态` | `正在从后端重新获取可信快照。在完成前，不展示本地旧状态为当前结果。` | `请稍候` |
| 聊天模型不可用 | `对话能力暂时降级` | `我暂时无法处理开放式对话。状态查询和可明确识别的本地操作仍可尝试。` | 提供 V1 支持的明确表达示例 |
| 模型不可用且意图不明 | `未执行` | `当前无法可靠理解这个操作，因此没有执行。请说明设备和目标状态后重试。` | 重新明确设备与动作 |
| 环境数据不可用或过期 | `当前数据不可用` | `暂时无法获得可信的当前环境读数。我不会用历史消息或猜测补值。` | 数据恢复后重试 |
| 设备服务不可用 | `设备操作不可用` | `当前无法确认设备状态，因此没有执行操作。` | 恢复后先查询状态，再决定是否重试 |
| Mock/Replay 优化器不可用 | `模拟优化暂停产生动作` | `Mock/Replay 暂时不可用，不会创建新的模拟优化任务，也不会继续产生候选动作。` | 聊天、查询和允许的单设备控制可独立使用 |
| 回复生成失败 | `已使用固定回复` | `自然语言回复暂时不可用；以下内容来自系统已校验的状态或回执。` | 继续查看结构化结果 |

任一依赖降级都不得转写为“系统已自动处理”，也不得绕过确认有效期、状态版本、动作屏蔽或策略复核。

## 4. 执行与任务结果

| 结果 | 必须出现的语义 | 推荐模板 |
|---|---|---|
| 请求已受理/执行中 | 尚未成功 | `请求已受理，正在等待执行结果。这不表示设备状态已改变。` |
| `succeeded` | 成功回执、实际状态、来源 | `已{actionLabel}。当前状态：{actualState}；结果来源：{source}。` |
| `noop` | 执行前已是目标状态，没有重复执行 | `{deviceLabel}已处于{actualState}，本次未重复执行。` |
| `partial_success` | 明确写“部分成功”，逐项展示 | `部分成功：{successCount}/{totalCount} 项已完成。已完成：{successItems}；未完成：{failedItemsAndReasons}。` |
| `failed` | 明确失败，不暗示状态改变 | `操作失败：{safeReason}。未确认设备已达到目标状态。{retryAdvice}` |
| `timed_out` | 明确超时且最终状态未知 | `操作等待超时，最终状态暂时未知。请先查询设备状态，再决定是否重试。` |
| `unknown` | 无法确定最终状态 | `当前无法确定操作的最终结果。我不会把它记为成功；请先重新查询状态。` |
| 任务已创建 | 只陈述任务状态，不代表设备动作成功 | `任务已创建，当前状态：{taskStatus}。设备动作结果将按每项回执另行展示。` |

对多动作场景，每项都展示设备类型、请求动作、回执状态和安全原因；整体只有在所有必需项都有成功回执时才能写“全部成功”。

## 5. 确认、澄清、拒绝与错误

| 类型 | 标题 | 文案要求 |
|---|---|---|
| 待确认 | `等待确认` | 显示计划摘要、影响、来源、有效期，并同时提供“确认”和“取消”；说明可用文本完成同等操作 |
| 澄清 | `需要补充信息` | 只询问当前意图缺失的最少信息，不暗示已执行 |
| 拒绝 | `这个请求不能执行` | 说明 V1 范围或安全原因，可能时给出受支持的替代操作 |
| 错误 | `暂时无法完成` | 使用公开错误语义和 `retryable` 给出重试建议，不显示内部错误 |

## 6. 任务状态用语

| 结构化状态 | 用户可见文字 |
|---|---|
| 待确认计划 | `待确认（尚未创建任务）` |
| `scheduled` | `待运行` |
| `running` | `运行中` |
| `paused` | `已暂停` |
| `stopped` | `已停止` |
| `failed` | `已失败` |

任务状态以结构化字段为准，不从旧聊天消息或浏览器本地 Mock 状态恢复。
