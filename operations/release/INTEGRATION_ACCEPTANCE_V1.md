## 5. Mock/Replay 与声明边界

- [ ] Mock 环境指标同时展示 Mock 标识和观测时间。
- [ ] Replay 展示回放标识，不称为实时感知或实时模型决策。
- [ ] 模拟优化在模式选择、确认摘要、任务状态、每轮结果中均保留“模拟优化”。
- [ ] 无合法候选动作时明确写“本轮未执行”，不伪造收益或回执。
- [ ] 页面、回复、日志、事件和验收结论不宣称真实模型、真实设备、真实 DQN、真实节能或健康收益。

## 6. 执行回执与降级

| 用例 | 通过标准 | 证据/结果 |
|---|---|---|
| `succeeded` | 只有成功回执触发成功文案，且展示实际状态和来源 |  |
| `noop` | 展示“已处于该状态”，不产生新的设备执行记录 |  |
| `partial_success` | 标题明确写“部分成功”，逐项区分已完成与未完成 |  |
| `failed` | 不声称状态已改变，安全说明失败原因和可行下一步 |  |
| `timed_out` | 同时显示“超时”和“最终状态未知”，建议先查询再重试 |  |
| `unknown` | 明确不记为成功，要求重新查询可信状态 |  |
| 模型不可用 | 高确定本地查询/控制可独立工作；无法可靠识别的操作不执行 |  |
| 设备服务不可用 | 聊天/一般知识可用；设备动作不执行、不写成功 |  |
| Mock/Replay 不可用 | 不创建新模拟优化任务，不继续产生候选动作，其他独立能力不受影响 |  |
| 任务替换中旧任务停止失败 | 新任务不得创建，旧任务状态保持可解释 |  |

## 7. 事件失败不影响主链路

分别对状态查询、单设备幂等控制、确认计划、任务状态迁移和多动作回执执行以下对照：

1. 在事件接收器正常时记录 HTTP 响应、业务状态、回执和事件。
2. 使事件发送分别返回失败、抛出异常和超时；重复同一业务用例。
3. 对比前后两次的结构化响应、策略结果、任务版本/状态和执行回执。

- [ ] 事件失败没有导致业务请求失败或改变公开结果。
- [ ] 事件失败没有导致策略绕过、重复执行、重复迁移或丢失回执。
- [ ] 事件失败仅进入脱敏的可观测故障信号，不回写业助手响应正文。
- [ ] 如使用队列或重试，重试不携带禁止字段，且不发生无界重试。

## 8. 敏感数据不落日志/事件

使用仅用于测试的唯一标记字符串（例如 `SENSITIVE_TEST_MARKER_<run-id>`）放入合成用户消息和合成个人信息字段；不得使用真实 Key、Secret 或 Token。完成正常、错误、拒绝、超时和依赖降级路径后，在应用日志、前端控制台、事件输出、重试/死信介质中搜索该标记。

- [ ] 标记字符串未出现在任何日志或事件输出中。
- [ ] 事件不包含用户完整输入、助手完整回复、完整会话、提示词或模型原始输出。
- [ ] 日志和事件不包含未脱敏姓名、联系方式、精确住址、自由文本设备名、设备凭据或可执行连接信息。
- [ ] 错误路径不包含内部堆栈、文件路径、依赖 URL 或异常原文。
- [ ] 事件只使用契约信封和当前事件最小属性白名单，未出现自由形式 `metadata`。
- [ ] 不读取、打印或验证任何真实环境变量凭据值。
