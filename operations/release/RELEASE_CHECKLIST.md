# 本地 V1 发布检查

## 1. 发布定义

本清单的“发布”仅指本地 V1 联调包或演示包，不表示生产上线、真实设备接入、真实模型接入或收益验证完成。每次检查应记录构建或提交标识、执行人、时间和证据位置。

## 2. 阻断性能力声明

- [ ] 首屏、AI 对话、设备、任务摘要与结果页面的 Mock 数据均明确标识“本地 Mock”或“仅供联调”。
- [ ] Replay 内容均标识“Replay 回放”和“非实时数据”。
- [ ] 三种优化模式在入口、确认、任务状态和结果中均显示“模拟优化”。
- [ ] 页面、助手回复、README、演示话术和截图不宣称真实模型、生产 AI 或 AI 已自主接管。
- [ ] 不宣称真实传感器、真实 MQTT、真实设备控制或实时家庭环境。
- [ ] 不宣称真实 DQN、`live_model` 或真实在线优化。
- [ ] 不宣称已产生或验证真实节能、减排、健康改善或舒适性收益。
- [ ] 不把本地测试、Mock 结果、Replay 回放或历史报告表述为正式验收或生产结果。

任一项不通过时，禁止标记为“V1 可交付”。

## 3. 契约与连接

- [ ] 联调基于已接受且版本化的 v1.0.0 共享契约，前后端不使用未接受的字段作为稳定依赖。
- [ ] `GET /v1/health` 显示 `mode=local_mock`，不返回环境变量、文件路径、内部堆栈或凭据。
- [ ] 页面首次加载、刷新和重连均通过 `GET /v1/bootstrap` 获取后端快照。
- [ ] 后端未连接时显示明确降级文案，不把浏览器旧 Mock 状态冒充为后端可信状态。
- [ ] 结构化业务错误不依赖 HTTP 非 2xx 判断；前端读取 `responseType` 和 `error.code`。
- [ ] 默认后端地址仅绑定 `127.0.0.1`，前端不包含真实服务地址。

## 4. UI 与内容

- [ ] 首页、设备、AI 对话和我的四个页面均可访问。
- [ ] V1 烹饪守护和三种模拟优化模式可从 AI 对话完成；旧快捷场景不自动映射为未定义任务。
- [ ] 确认摘要有明确的确认/取消操作，并告知可用文本完成同等操作。
- [ ] 任务状态能以文字区分待确认、待运行、运行、暂停、停止和失败，不只靠颜色。
- [ ] 错误、拒绝、澄清、执行中、成功和部分成功文案可区分。
- [ ] 执行超时和状态未知均不使用成功表述，并建议先查询状态再重试。
- [ ] 多动作部分成功逐项展示，任务创建成功不冒充设备动作成功。
- [ ] 健康文案不诊断、不保证环境安全、不替代专业医疗建议。

## 5. 技术与隐私

- [ ] 静态资源无 404，控制台无未处理运行错误。
- [ ] Manifest 可读取，Service Worker 不引用已删除资源。
- [ ] 页面、打包产物、网络响应、日志和事件不包含 API Key、Secret、Token、设备凭据或可执行连接信息。
- [ ] 事件和日志不包含完整敏感对话、未脱敏个人信息、模型原始提示词/输出或内部堆栈。
- [ ] 事件符合 `analytics/EVENT_CATALOG.md` 最小白名单。
- [ ] 事件发送失败测试证明主链路响应、策略、任务和执行结果不受影响。

## 6. 验收与证据

- [ ] `release/INTEGRATION_ACCEPTANCE_V1.md` 所有适用项均有可重复的证据，未测项不写“通过”。
- [ ] 证据明确标记数据源为 Mock 或 Replay，不使用旧 AI V1、Phase A、DQN 路线或历史报告作为通过证据。
- [ ] 契约缺口、未实现能力和未通过项已明确记录，没有通过降低断言或改写验收目标制造通过。
